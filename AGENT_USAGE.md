# Agent Usage Documentation

This document outlines how AI coding tools were used in the development of the ClaimWise AI assessment project, in compliance with Aggroso submission requirements.

## 1. AI Coding Tools Used
* **Antigravity** (Google DeepMind agentic coding assistant) - Primary tool for codebase inspection, module-wise implementation, debugging, test generation, and documentation.
* **ChatGPT** (OpenAI) - Used occasionally for high-level architectural brainstorming and checking edge cases for prompt design before integrating into the backend `ExternalLlmClient`.

## 2. How AI Tools Were Used
* **Project Planning**: AI was used to map out the required entities (ExpenseClaim, Policy, AiReview, User) based on the Problem 1 description.
* **Architecture Design**: AI tools recommended the dual-engine approach (Deterministic + AI) to ensure safety and prevent LLM hallucinations from making final decisions.
* **Module-wise Implementation**: Antigravity generated boilerplate for Spring Boot entities, repositories, and controllers, as well as React/Vite frontend scaffolding.
* **Debugging**: When encountering React Router v7 future flag warnings or backend CORS issues, AI was used to identify the root cause and provide exact configurations.
* **Test Generation**: Antigravity was instructed to generate comprehensive JUnit tests targeting duplicate claim detection, AI JSON parsing, and role-based access.
* **Documentation**: AI assisted in drafting the README.md and structuring this usage report.

## 3. Representative Prompts

**Project Architecture**:
> "Design a Spring Boot architecture for an Expense Claim system where claims must pass hard deterministic rules (like amount > 0) before being sent to an external LLM for policy review. Ensure the LLM cannot make the final approval decision."

**Backend Implementation**:
> "Create a Spring Boot service `DeterministicValidationService` that takes an `ExpenseClaim`. It needs to check if the amount exceeds the limit specified in the `Policy` table. Return a structured `ValidationResult` with a list of `ValidationIssue`."

**Frontend Implementation**:
> "Create a React component `ClaimDetailPage.jsx`. It should fetch claim details, deterministic issues, and the AI review. Display the AI analysis confidence score as a progress bar, and show deterministic issues as red/yellow badges."

**AI Integration**:
> "Write a Java `ExternalLlmClient` using `java.net.http.HttpClient` that sends a prompt to OpenAI's API. Request `json_object` format. If the network call fails or times out, throw a clear exception so the service can trigger the fallback engine."

**Testing**:
> "Write a JUnit test `testDuplicateApprovalFails` for `ReviewDecisionService`. Create a claim, have the reviewer approve it, and then try to approve it again. Assert that an exception is thrown on the second attempt."

**Final Audit**:
> "Do NOT modify any code. Compare the current ClaimWise implementation against the original Problem 1 requirement. Specifically verify the 'TOTALS' requirement. Answer 1. Is there an implemented deterministic totals validation? ..."

## 4. Delegated Work
* **Delegated**: Scaffolding entity classes, generating standard CRUD repositories, writing boilerplate React components, styling with CSS (the 'Job Scheduler' theme), and writing comprehensive test cases.
* **Not Delegated**: The conceptual design of the dual-engine validation, the decision to use a Fallback Engine for reliability, database schema relationships, and the final manual end-to-end testing and validation.

## 5. Important Agent Mistakes or Rejected Suggestions
* **Mistake: Fake LLM Calls**: Early in development, the AI suggested an `AIReviewService` that just returned hardcoded string responses to simulate AI. This was rejected. The agent was explicitly instructed to write a real `ExternalLlmClient` making actual HTTP requests to an LLM provider.
* **Mistake: Missing Duplicate Tests**: Initial verification tests generated by the AI did not include duplicate decision test coverage (e.g., preventing a reviewer from approving an already approved claim). This gap was identified through a separate audit, and the agent was instructed to add `testDuplicateApprovalFails` and `testDuplicateRejectionFails`.
* **Mistake: Hardcoded USD**: The AI initially built the frontend hardcoding the `$` symbol and `USD`. This was rejected, and a subsequent prompt forced the agent to refactor the entire application to use INR (`₹`).
* **Mistake: Missing Database Grounding**: The AI initially allowed the LLM to cite any policy it wanted. This caused hallucinations. The code was heavily modified to include a strict validation loop (`parseAndValidateLlmResponse`) that strips any policy citations not physically present in the database.

## 6. Verification Process
Code generated by AI was rigorously checked through:
1. **Source Code Inspection**: Manual review of critical files like `SecurityConfig`, `AIReviewService`, and `ExternalLlmClient` to ensure no security flaws or bad practices.
2. **Maven Tests**: Running `mvn clean test` continuously to verify that logic (especially the fallback engine and deterministic validation) held up against edge cases.
3. **Maven Package Build**: Running `mvn clean package` to ensure a clean artifact without compiler warnings.
4. **Frontend Production Build**: Running `npm run build` to ensure the Vite build process succeeds without chunking or dependency errors.
5. **Security Checks**: Auditing `.env` usage, `.gitignore`, and ensuring no API keys or JWT secrets (originally hardcoded) were committed to the final repository.
6. **End-to-End Workflow Verification**: Manually logging in as `employee@claimwise.com`, submitting a claim, logging out, logging in as `reviewer@claimwise.com`, and ensuring the AI review appeared correctly before approving.
